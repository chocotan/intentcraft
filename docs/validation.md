# 验证记录

此文件记录实际检查的范围，不承诺所有模型或宿主上的确定行为。

## 检查类型

- `npm test`：无第三方依赖的结构、链接、手动触发字段、规则标记和包内容检查。
- [行为场景](../tests/scenarios.md)：模型/宿主评估输入，未执行的场景不算通过。
- 独立审查：只读检查当前文档、边界和交接一致性，不替代宿主行为实测。

## 0.1.0 首轮执行

### 静态与分发

`npm test` 和 `npm pack --dry-run --json --ignore-scripts` 已运行通过。
检查了两个独立安装单元、布尔手动触发字段、skill-local 引用、主要规则标记、
20 个场景定义以及安装包白名单。`example/` 和 `.pi/` 不进入安装包。
这些只是静态契约与分发检查，不代表 20 个场景都已执行。

### Pi 实际加载检查

在 Pi **0.83.0** 上运行 `python3 tests/check_pi.py`，通过：

- 两个 skill 都能通过 `get_commands` 找到手动入口。
- 普通提示的实际模型请求中，不包含这两个 skill 的自动发现条目。
- 同时加载的非隐藏测试 skill 出现在系统提示中，作为阳性对照。
- 两个 `/skill:名称` 都展开正确正文并保留用户参数。

采用临时 HOME/配置目录、禁用额外发现、仅本地回环假模型，三个请求全部发送给
该假模型；没有外部模型请求、真实凭据或全局配置修改。它验证宿主加载机制，
不验证真实模型如何服从提示词。支持字段但尚未测试的其他 Pi 版本不在结论内。

初次零模型 RPC 探查使用了错误的正文匹配字符串，未通过测试断言；实际正文已
展开。修正测试方法后使用上述带阳性对照的完整检查，不把初次尝试计为通过。

### 模型行为样本

在 Pi 的独立 agent 上，用当前会话模型 `newapi-ge/gpt-6-astra` 做了两类评估。
被测 agent 读取 skill 和按需 reference，但没有读取场景判据。

| 样本 | 实际观察 | 覆盖限制 |
|---|---|---|
| S06 / S17：只研究 README 陷阱 | 读取主 skill、研究 reference 和五个 fixture 文件；指出消费者不检查 `ready`，区分文档、静态实现与未执行测试；没有写计划或运行样例代码 | 一次小型人工 fixture，不代表真实大仓库研究完整性 |
| S02：错字最简处理 | 短答复，不建档、不研究竞品，承认没读仓库无法给具体路径 | 三输入批次中的一次路由演练，不是独立宿主端到端会话 |
| S04：纯后台导入草案 | 给出数据/幂等/失败方向，无 UI/原型/技术栈强加，列未决项并标为非执行就绪 | 无真实仓库，只评价分流与授权边界，不宣称实施方案完整 |
| S03：直接删一行账号 | 指出关联数据、会话与保留义务风险，不执行删除 | 路由演练，不证明实际数据库防护 |

研究 fixture 的可复现内容在 [tests/fixtures/readme-trap](../tests/fixtures/readme-trap/README.md)。
实际工具轨迹由主会话核对：研究使用读取/目录调查工具，没有修改或执行动作；
路由演练只有读取工具。这里保存观察摘要，不发布私有会话转录。

### 独立审查

两次自定义 reviewer 启动均在没有工具调用和报告的情况下结束，未计为有效审查。
随后用全新的通用 agent 上下文执行独立只读审查，实际完成 28 次工具调用，
结论为：**就已覆盖范围无阻塞或重要问题，可进入下一步**。

该 reviewer 完整读取两份 skill 主文件、六份 references、README、manifest、
检查脚本、场景与验证记录，补查相关分发和 Pi 文档；独立重跑 `npm test` 与
`python3 tests/check_pi.py` 均通过。没有修改项目、创建子 agent 或执行陷阱 fixture。
审查时两个主文件的 SHA-256 前缀为 `955d9b9d6b30`、`d46fa0e0bee08`。

审查没有重跑前述真实模型样本，因此没有将作者记录冒充独立实测。
当时文件尚未暂存，空的 `git diff --check` 不被计为整份项目的空白检查；
发布流程另在显式暂存新项目文件后执行 `git diff --cached --check`。
