# ic-prepare
把问题准备到产品方案、设计或可交接计划，不写生产代码。用户显式调用后，同主题可继续；完成、取消或转向无关主题即停止。不自动调用其他 `ic-*` skill。

## 主产出与质询

每次先选一个主产出：`product`、`requirements`、`ui`、`design`、`prototype`、`plan` 或 `grill`，只加载所需方法。产品地图、需求、UI、Design、原型和 Plan 可组合，但不会默认全做；用户明确组合时也不填空或扩大授权。

代码、资料和已有研究能回答的事实自行查；只问会改变结果的取舍，每次一个问题并给推荐、依据和代价。用户要求“grill me／挑战方案”时，按依赖深入功能边界、用户旅程、UI层级、交互状态和视觉方向；检查组合矛盾，视觉分歧用页面、线框或样式对比。用户停止即结束，推荐不等于选择。

## 方法

- **产品地图**：新产品、整体体验或多个关联功能才整理目标用户、结果、主旅程、能力关系、范围、非目标、候选和关键未知。
- **需求**：写角色、前置条件、动作、成功/失败/取消/重试、权限、状态和可观察验收；区分事实、假设、建议和用户选择。
- **Design**：写职责、数据/请求/状态流、模块/API/组件边界、错误路径、技术取舍、不变契约和可下放细节；不写代码。
- **UI 契约**：UI 影响理解或验收时，标明当前/目标/示意，说明旅程、页面结构、信息层级、关键状态、稳定空间关系和可调整视觉细节。按需覆盖空、加载、错误、禁用、执行中、响应式或确认；动态状态说明宿主、遮挡、裁切和布局稳定性。允许按授权制作隔离的探索性 HTML 原型，但它不是生产代码；原型、截图和线框不替代行为与验收。
- **Plan**：按可验收结果拆单元，优先最小端到端路径；写需求对应、范围、方案/接口、依赖、顺序、验证、可下放细节、风险、暂停和回退。关键未知未解时只交条件草案，不标为可交接。

## 产出与交接

由 Agent 判断准备结果是否需要持久化，不以用户是否逐字说“保存”为唯一条件：包含多轮决策、可复用需求、Design、Plan、关键取舍或后续交接价值时，默认落盘；一次性短答、探索性草稿或用户明确要求不写文件时，只在回复中交付。用户明确要求保存或不保存时优先遵循。每次明确说明 `已落盘：<path>` 或 `未落盘：<理由>`。

需要落盘时，只写入目标业务项目根目录下的 `docs/ic-prepare/YYYY-MM-DD-<topic>.md`；不写入 skill 安装目录。相对目标业务项目根目录解析，默认是调用时工作目录。同一阶段、用户补充或新研究结果出现时，定位并直接更新原文件对应章节，不机械地在结尾追加；新的 Design/Plan 阶段或范围变化才新建日期文件。多个匹配文档不按日期猜，先按路径、状态和引用消歧，无法确认就询问。按需包含：

```text
产品地图 · 需求契约 · Design/UI 契约 · 实施计划 · 未决与验证
```

状态使用 `草案`、`待用户确认`、`可交接`；可交接不等于批准或执行授权。默认可直接回复，不为简单问题建空文档。交付前检查需求覆盖、组合矛盾、关键失败状态、Design/计划一致性、单元依据和验证；行为或契约变化交用户决定。需要独立准备审查时调用 `ic-design-review`，需要实现时调用 `ic-do`。

## 授权边界

研究、文档、原型/实验、实现、提交和发布分别授权；确认方向不扩大授权。需要运行、安装或编译外部项目时，先说明目的、成本和风险并询问用户；同意后隔离执行，否则退回静态研究并标未验证。不自动修复、提交、发布或调用下一 skill。
