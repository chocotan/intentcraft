# 前端方法选择与适配

这是中立的方法参考，不是新的 Skill 入口；主会话或受派代理都可按任务读取。读取不启动任何 IC 阶段，不授予安装、写入、用户确认或阶段推进权限；非 IC 任务也不因此创建阶段文档。

## 先确定适用范围

- 从任务取得目标与保持项、当前工作性质（取证/准备/实现/只读审查）、已确认设计、实际技术栈、允许的写入与环境、验收及资源归属。缺关键输入只报告相应缺口，不重新组织产品访谈。
- 用户偏好来自当前任务和适用项目/全局指引；本参考不内置个人的方案数量、屏幕尺寸或品牌偏好。需要委派时主会话明确传递这些约束，不假定子代理已读到。
- 一次选择一套主方法，再按具体问题补充专项参考，不串行执行所有 Skill 的完整流程。无需专项方法的简单任务直接按项目约定处理。

## 按问题选择方法

下列名称用于定位已安装 Skill，不是相对于项目 cwd 的路径。先用运行时元数据定位其 `SKILL.md`；manual-only 未暴露入口时按宿主当前技能发现配置查找。配套路径从实际 Skill 目录解析，执行脚本保持目标项目 cwd。不假定安装位置，不把白名单当文件权限，也不自动安装缺少的可选 Skill。

| 当前问题 | 主方法与按需补充 |
|---|---|
| 产品界面的流程、状态与信息层级 | `impeccable` 的 `reference/shape.md`、`reference/operate.md`；复杂任务再补 `qiaomu-design` 的 `references/carbon-patterns.md`、`references/carbon-components.md` |
| 新视觉方向与可比较原型 | `qiaomu-design`：诊断、方向发散和预览；方案数量与确认方式以任务约束为准 |
| 方向已定的营销页、品牌页、作品集 | `design-taste-frontend`：采用适用的表达方法，不把营销习惯套给工具界面 |
| 指定参考产品的视觉与交互语言 | `style-extractor`：有证据的语义 tokens、状态与动效提取，不代替完整竞品/源码研究 |
| 色板、字体、图表和设计数据查询 | `ui-ux-pro-max`：定向查询并说明适用性，不用数据库推荐覆盖已确认设计 |
| 已采用或已批准采用的组件体系 | 与实际项目匹配的 Skill，例如 `shadcn`；核对组件源码、配置、版本与真实 API，不先换库再做功能 |
| 表单、导航、键盘与焦点 | `web-interface-guidelines`：结合实际交互与平台检查；技术例外按下文核验，不把宽泛禁令当作实测结论 |
| 异常健壮性、技术/体验审查与交付打磨 | `impeccable` 的 harden、audit、critique、polish 参考按问题选用；只读任务提建议，不执行其中的修复步骤 |
| 现有能力不足，需要选库 | `pick-ui-library`：先核对已安装依赖与原生能力，建议不等于安装或替换授权 |
| 动效、物理手势、移动端 Web/PWA | 按问题选 `animate`、`apple-design`、`mobile-native`，不整组加载；简单过渡优先现有能力 |
| 动效评审、发现机会、术语 | 分别用 `review-animations`、`find-animation-opportunities`、`animation-vocabulary`，审查/建议不自动变成实现 |
| 中文排版 | 按需读 `qiaomu-design` 的 `references/chinese-typography.md`，结合实际字体支持、语言与页面类型核对 |
| 浏览器实查与验证 | `agent-browser`，先获取当前 CLI 的 core 指南；专项探索 QA 才补 dogfood，不沿用其全站范围或问题数量目标 |

先读所选 Skill 的入口，再只读当前任务需要的配套材料；资料缺失或工具不可用时说明替代依据与证据限制，不能声称执行了未取得的方法。

## 适配上游流程，不接管任务

| 上游指令 | 本任务中的适配 |
|---|---|
| qiaomu 等待用户、管理 watcher、进入生产实现 | 方向任务只完成授权的预览与说明后返回；用户沟通和阶段推进归主会话。预览服务由任务指定负责人管理，不让子代理占住运行等人 |
| impeccable 的访谈、init、context 与后续修复 | 已确认内容不重问；问题交主会话。初始化、安装或持久化须符合任务授权，不因缺文档自动扩展任务。只读审查不执行修复步骤 |
| style-extractor 的固定平台路径与 Chrome MCP | 用任务指定的浏览器能力和输出目录；保留必要指南、语义值与证据，不照搬 Windows 路径，不为模板要求编造组件/状态 |
| ui-ux-pro-max 的持久化与主设计文件 | 默认只取建议；只有任务明确要求才保存。沿用已有设计入口，不创建与项目文档竞争的事实来源 |
| shadcn 或其他文档中的命令模板、安装与覆盖 | 模板不等于命令已执行。先核对本地配置和版本，再在授权内取文档或执行操作；不默认安装、覆盖或切换组件体系 |
| 上游“用户偏好账本”、自动记忆和自进化 | 当作来源材料，不自动视为当前用户偏好；普通产品任务不得顺便修改全局 agent、Skill 或偏好账本 |
| 原型也要通过整套生产检查表 | 只检查当前阶段、平台与目标的适用项；无关项说明不适用，必要但未完成项标未验证，不通过扩大范围凑清单 |

只读审查始终不改被审材料；原型中的模拟行为不是生产完成证据。工具可用、Skill 建议或检测命中都不能扩张任务授权。

## 技术规则冲突

- 优先核对实际项目版本、实现、可靠文档和测量，不依据“必须/禁止”措辞的强弱裁决。安全、可访问性和真实验收不能用审美偏好豁免；已确认设计也不能把错误 API 变成可用 API。
- 动效默认采用低开销、可中断方案，避免 `transition: all`。短时 accordion 高度过渡、clip-path 或轻量 blur 可在有目的并检查开销后采用；reduced-motion 可用纯 fade 或静态反馈，不因缺少 transform 否决。
- 不凭属性名或 Motion shorthand 宣称硬件加速或掉帧；按实际库版本与目标负载核对。应用壳与营销 Hero 的视口单位按用途选择，不套同一条硬规则。
- 上游规范发生真实冲突时，报告冲突位置、采用依据和剩余风险。工程事实自行调查，产品取舍交用户；仅暂停受影响部分，不静默任选一份，也不重写全部上游资料。

## 资源与证据

- 浏览器会话、预览服务、容器等按任务约定负责人、使用者和停止条件。使用独立会话，结束时只清理自己负责且不再需要的资源，不关闭他人的服务。
- 输出位置和产物归属由任务或阶段指定，本参考不另建报告目录。保留可复核截图、步骤、实际命令/版本和结果；临时 URL 或临时进程不是唯一交付物。
- 扫描辅助发现缺陷，不能证明美观或完整功能；已有自动扫描不重复。视觉打磨按任务预算收敛，不凑问题；轮次耗尽不豁免功能缺陷。
- 原型、生产功能和只读审查分别给证据。模拟不冒充真实集成，截图不替代必要自动化；缺环境或授权如实报告，由主会话安排下一步。
